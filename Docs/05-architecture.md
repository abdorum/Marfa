# 05 · المعمارية

## الهدف المعماري الأول

**النواة مستقلة عن المصدر.** المنتج عارض عام لمعلومات الطالب ([01-vision.md](01-vision.md))، وكل مصدر مجرد محوّل: PeopleSoft اليوم، وملف Excel أو منصة تعلّم أو واجهة رسمية غدًا. إضافة مصدر يجب ألا تمس الواجهة ولا النموذج الموحّد ولا منطق التطبيق. لذلك نعتمد نمط **Ports & Adapters** (المعمارية السداسية):

```
┌──────────────────────────────── المتصفح (PWA) ────────────────────────────────┐
│                                                                               │
│   الواجهة (screens, ui)  ◀──  المخزن (store)  ◀──  النواة (core)                │
│                                    ▲             نموذج موحّد · اشتقاقات · رعد   │
│                                    │                    ▲                     │
│                                    │          ملف المؤسسة (institution)        │
│                        ┌───────────┴────────────┐                             │
│                        │ المنفذ: StudentDataSource│                            │
│                        └──┬────────┬────────┬───┘                             │
│        ┌──────────────────┘        │        └───────────────┐                 │
│   الفئة د: PeopleSoft       الفئة ب: official      الفئة أ: demo، وملفات (النسخة 2) │
│   (استخراج في المتصفح)      (عقد التكامل)          (كلها في المتصفح)               │
└──────────┬────────────────────────┬────────────────────────────────────────────┘
           │ HTTPS                  │ HTTPS
┌──────────▼──────────────┐  ┌──────▼──────────────┐
│ Worker رعد (الحافة)      │  │ واجهة رسمية للمؤسسة  │
│ جلسات + حماية. بلا تخزين │  │ أو جسر تستضيفه       │
└──────────┬──────────────┘  └─────────────────────┘
           ▼
     sis.bmc.edu.sa
```

الفئات من أ إلى د مرتبة حسب المخاطرة، ومعرّفة في [20-adapters.md](20-adapters.md).

## الطبقات

| الطبقة | المسؤولية | ما يُسمح لها | ما يُمنع عليها |
|---|---|---|---|
| **core/model** | أنواع النموذج الموحّد (Snapshot، Course…) | TypeScript فقط | DOM، fetch، أي شيء يخص PeopleSoft |
| **core/derive** | حسابات: الأسبوع الدراسي، المحاضرة التالية، التنبيهات، نسبة الغياب من الحد | دوال صافية | الحالة والإدخال والإخراج |
| **core/bot** | محرك المهام: الحالات، وسياسة إعادة المحاولة، والمهلة، والاستئناف | منافذ مجردة | معرفة المصدر |
| **adapters/*** | تنفيذ المنافذ لمصدر معيّن | ما يحتاجه المصدر | تغيير النموذج الموحّد |
| **web/store** | اللقطة الحالية والمهام والإعدادات، والحفظ في IndexedDB | core | — |
| **web/ui + screens** | العرض والتفاعل | store و core/derive و i18n | استدعاء المصدر مباشرة |
| **edge (functions)** | الجزء الذي **يجب** أن يعمل على سيرفر في كل محوّل | الشبكة | التخزين، والتسجيل في السجلات، والتحليل الثقيل |

**القاعدة الذهبية:** الواجهة لا تعرف أي مصدر. كل ما تراه هو `Snapshot` و`Job` وملف المؤسسة.

## المنفذ (العقد)

```ts
// يقرأ كل ما يمكن قراءته ويعيده بالنموذج الموحّد.
interface StudentDataSource {
  id: SourceId;
  manifest: AdapterManifest;                      // النسخة 1: الفئة، وما يقدّمه، وما يحتاجه، وصائنه
  sync(ctx: SourceContext): Promise<SyncResult>;  // SyncResult = Partial<Snapshot> + provenance
}
```

**لا يوجد منفذ للكتابة،** ولن يوجد: المنتج للعرض فقط (ADR-020). `SourceContext` يحمل بيانات الدخول إن احتاجها المحوّل (في الذاكرة فقط)، ودالة إرسال الأحداث، وإشارة الإلغاء (`AbortSignal`).

## ملف المؤسسة

كل ما يختلف من مؤسسة لأخرى يجتمع في ملف واحد، لا متفرقًا في الكود (النسخة 1):

| الإعداد | مثال لكليتك |
|---|---|
| الاسم بالعربية والإنجليزية | كلية البترجي الطبية |
| المحوّل وإعداداته | `peoplesoft`، ورابط النظام، والصفحات المسموحة |
| مقياس المعدل | يُقرأ من النظام |
| حد الغياب الافتراضي | 25% |
| نوع الفترات | فصول |
| التقويم وبداية الأسبوع | ميلادي، والأحد |
| التواصل | قناة تيليجرام |

## محوّل PeopleSoft: لماذا هو منقسم بين المتصفح والحافة

| الجزء | المكان | السبب |
|---|---|---|
| الجلسة، والدخول، والكوكيز، والتدفقات متعددة الخطوات | **الحافة** (Cloudflare Function) | المتصفح ممنوع من قراءة صفحات نطاق آخر (CORS) |
| استخراج البيانات من HTML، والاستخراج العام، والتحويل للنموذج | **المتصفح** | حد المعالجة في الخطة المجانية (10ms)، وبيانات الطالب لا تُحلَّل على أي سيرفر |
| اختيار الصفحات المسموحة وسياسة المحاولات | **مشترك** (ملف واحد) | مصدر واحد للحقيقة |

### واجهة الحافة (v1)

تعمل في Worker رعد المستقل (`raad/`)، والموقع يمرّر إليه `/api/v1/*` داخليًا. كل الطلبات بلا حالة، وكل طلب يفتح جلسة جديدة ويغلقها.

| المسار | المدخل | المخرج |
|---|---|---|
| `POST /api/v1/sync` | بيانات الدخول + `pages[]` من القائمة المسموحة | `{ pages, errors, log, fetchedAt }` |
| `GET /api/v1/health` | — | هل يصل الخادم إلى نظام الكلية؟ (صفحة الدخول فقط) |
| `POST /api/v1/metrics` | عدادات مجهولة، إن وافق الطالب | — |

الإصدار (`v1`) في المسار حتى تبقى التطبيقات المثبّتة القديمة تعمل عند تغيير الواجهة.

## المرونة: الاستخراج العام وصفحة "المزيد"

النظام لا يعرف مسبقاً كل الحقول، لكنه **يعرف شكل PeopleSoft**:

1. **المستخرجات المعروفة** تحوّل ما نعرفه إلى النموذج الموحّد: الجدول، والدرجات، والغياب، والاختبارات.
2. **المستخرج العام** يمر على كل صفحة مجلوبة ويستخرج:
   - **الجداول (Grids):** جداول PeopleSoft لها نمط ثابت (`win0div<GRID>$0` و `<GRID>$scroll$0` وصف عناوين). تُستخرج كـ `{columns, rows}`.
   - **أزواج الحقل والقيمة:** حقول العرض فقط (`PSEDITBOX_DISPONLY` وغيرها) مع تسمياتها.
3. لكل كتلة **بصمة ثابتة**: `pageKey + gridId` أو `pageKey + fieldId`.
4. **سجل الترقية** (`registry.json`): إذا كانت البصمة معروفة تذهب للمستخرج المخصص لها، وإلا تذهب إلى `snapshot.extras`.
5. صفحة "المزيد" تعرض `extras` كما هي، بعنوانها الأصلي، وتختفي الكتلة إذا اختفت من المصدر.
6. **ترقية كتلة إلى قسم كامل،** مثلاً جدول فعاليات ظهر غداً: نضيف إلى `registry.json` العنوان بالعربية والإنجليزية، وتعيين الأعمدة، والقالب (جدول أو قائمة أو تقويم). هذا **تعديل إعدادات وليس كتابة كود**.

### اكتشاف صفحات جديدة بأمان

طلب صفحة غير مسموحة يقتل الجلسة، لذلك:
- **القائمة المسموحة (allowlist)** هي المصدر الوحيد لما يجلبه التحديث العادي.
- **الاكتشاف** يقرأ ما يعرضه النظام نفسه للطالب: قوائم Student Center المنسدلة وقائمة البوابة. هذه القوائم لا تعرض إلا الصفحات التي يملك الحساب صلاحيتها.
- **تجربة صفحة جديدة تتم في "جلسة معزولة"** مستقلة عن جلسة التحديث. إن قُتلت الجلسة المعزولة لا يتأثر شيء آخر. تُسجّل النتيجة في "خريطة صلاحيات" مع مدة صلاحية، وتُرسل بإذن الطالب كبلاغ مجهول المصدر يساعد في توسيع القائمة للجميع.

## محرك رعد

التفاصيل في [08-bot-spec.md](08-bot-spec.md). باختصار: يعمل في المتصفح، وكل مهمة محفوظة في IndexedDB وتُستأنف عند فتح التطبيق، وكل محاولة طلب مستقل إلى الحافة. **لا تنفيذ في الخلفية على الخادم،** لأنه يحتاج حفظ بيانات الدخول. البديل للتذكيرات تصدير التقويم إلى الجوال.

## الحالة في الواجهة

```
IndexedDB ──▶ store (signals) ──▶ screens
   ▲              │
   └── persist ◀──┘          sync/job events ──▶ store.apply(patch)
```

- `snapshot`: آخر لقطة مدمجة. كل قسم له مصدر خاص به `{status, fetchedAt, error}`، فلا يمحو فشلٌ جزئي البيانات القديمة.
- `jobs`: المهام وسجلاتها.
- `prefs`: اللغة والمظهر وحد الغياب والموافقات.
- `vault`: بيانات الدخول مشفّرة (انظر [09-security-privacy.md](09-security-privacy.md)).

## الاختبارات

| النوع | ماذا يغطي |
|---|---|
| وحدات | core: الاشتقاقات، والدمج، وحالات البوت، وسياسة المحاولات |
| مستخرجات | كل مستخرج على **صفحات حقيقية مُجهّلة**. أي تغيير في PeopleSoft يظهر هنا أولاً |
| المطابقة | **نفس مجموعة الاختبارات** تعمل على كل محوّل: demo وpeoplesoft وofficial، وكل محوّل جديد. من ينجح فيها يُقبل ([20-adapters.md](20-adapters.md)) |
| الحافة | بوابة PeopleSoft مزيّفة تعيد إنتاج الأعطال الحقيقية: قتل الجلسة، والمهلة، وانتهاء الجلسة |
| شاملة (e2e) | Playwright على الوضع التجريبي، بمقاسي الجوال والكمبيوتر، باللغتين |

**أداة التقاط العينات:** سكربت للتطوير فقط يحفظ صفحات PeopleSoft من جلسة المطوّر، ويستبدل الاسم والرقم الجامعي والبريد بقيم وهمية قبل الحفظ.

## الوضع التجريبي (Demo)

محوّل `demo` يعرض بيانات طالب وهمي كاملة. له ثلاث فوائد:
1. **العرض للإدارة** دون الحاجة لحساب حقيقي ودون كشف بيانات أحد.
2. الاختبارات الشاملة.
3. تطوير الواجهة دون الضغط على PeopleSoft.

يُفتح من صفحة الدخول برابط `?demo`، ولا يظهر له زر.
