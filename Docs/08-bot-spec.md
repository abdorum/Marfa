# 08 · مواصفات رعد (البوت)

> رعد هو هوية المشروع: يتعامل مع النظام الأصلي ويتحمّل أعطاله، ويكرر المحاولة حتى يحصل للطالب على ما طلب، أو يخبره بوضوح لماذا لم يستطع.

## المهمة (Job)

```ts
interface Job {
  id: string;
  type: 'sync' | 'enroll.add' | 'enroll.drop' | 'enroll.swap' | 'discover';
  params: Record<string, unknown>;
  state: JobState;
  attempt: number;
  maxAttempts: number;
  deadline: string;                  // ISO — بعدها تتوقف المحاولات
  idempotencyKey: string;
  steps: StepEvent[];                // الخط الزمني المعروض للطالب
  result?: unknown;
  failure?: Failure;
  createdAt: string; updatedAt: string;
}

type JobState =
  | 'queued' | 'running' | 'waiting_retry' | 'verifying'
  | 'succeeded' | 'failed' | 'needs_input' | 'cancelled';
```

```
queued ──▶ running ──▶ verifying ──▶ succeeded
              │  ▲          │
     خطأ عابر │  │ الموعد   │ التحقق فشل
              ▼  │          ▼
          waiting_retry   running (محاولة جديدة إن بقي وقت)
              │
   انتهت المحاولات/الوقت ──▶ failed
   كلمة مرور خاطئة ──────▶ needs_input
   ألغاه الطالب ─────────▶ cancelled
```

## تصنيف الأخطاء وسياسة كل صنف

| الصنف | أمثلة | سياسة البوت |
|---|---|---|
| **جلسة** | `SESSION_EXPIRED` و `NOT_AUTHORIZED` | جلسة جديدة فوراً. حتى 3 مرات في المحاولة الواحدة |
| **عابر** | `TIMEOUT` و `UPSTREAM` و 5xx | انتظار متزايد مع عشوائية: 2، 4، 8، 16، 30، 30… ثانية حتى الموعد النهائي |
| **دخول** | `BAD_CREDENTIALS` | توقف فوري، والحالة `needs_input`. **لا تكرار أبداً،** لأن التكرار قد يقفل حساب الطالب |
| **عمل** | الشعبة ممتلئة، تعارض في المواعيد، متطلب سابق، خارج فترة التسجيل | توقف فوري، والحالة `failed`، مع رسالة النظام **كما هي** وترجمة مختصرة إن عرفناها. لا تكرار |
| **غير متوقع** | صفحة لا نعرف شكلها | توقف، والحالة `failed`، ونحفظ نسخة مُجهّلة من الصفحة محلياً للإبلاغ الاختياري |

## الحدود

| المهمة | أقصى عدد محاولات | المهلة الكلية |
|---|---|---|
| `sync` | 5 | 90 ثانية |
| `enroll.*` | 8 | 5 دقائق، ويستطيع الطالب أن يضغط "استمر" لتمديدها |
| `discover` | 1 | 30 ثانية، في جلسة معزولة |

**حدود عامة لحماية النظام الأصلي ولحماية المشروع:**
- مهمة كتابة واحدة فقط في كل وقت لكل طالب.
- مهمة تحديث واحدة في كل وقت، وتحديث تلقائي لا يتكرر أكثر من مرة كل 15 دقيقة.
- لا تقل المسافة بين محاولتين عن ثانيتين.
- **لا حجز آلي للمقاعد:** البوت لا يراقب شعبة ممتلئة ليحجزها عند فراغها.

## الإجراءات التي تكتب: أربع ضمانات

1. **معاينة:** قبل التنفيذ يعرض البوت ما سيحدث بالضبط: المادة والشعبة والمواعيد والتعارضات المتوقعة.
2. **تأكيد:** زر واحد واضح. لا يُنفّذ أي إجراء كتابة دون تأكيد صريح في كل مرة.
3. **عدم التكرار (Idempotency):** قبل كل محاولة يقرأ البوت الحالة الحالية: هل المادة مسجّلة أصلاً؟ هل هي في السلة؟ ثم يتخطى ما تم. فإذا انقطع الاتصال بعد الإضافة وقبل وصول الرد، لا تتكرر الإضافة.
4. **تحقق:** بعد التنفيذ يقرأ البوت الجدول أو قائمة التسجيل من جديد. النجاح يعني أن **المادة تظهر فعلاً**، لا أن النظام قال "تم".

## تدفق تسجيل مادة (مسودة، تُستكمل بعد الالتقاط)

```
1. SIGN IN
2. OPEN ENROLLMENT (SSR_SSENRL_CART)   ← اختيار الفصل إن طُلب
3. CHECK STATE                        ← هل المادة مسجّلة أو في السلة؟
4. ADD TO CART (classNbr)             ← قد تتبعها صفحة اختيار المكوّن (محاضرة/عملي)
5. PROCEED → FINISH ENROLLING
6. READ RESULT                        ← ✓ أو ✗ مع رسالة النظام
7. VERIFY                             ← قراءة الجدول من جديد في جلسة جديدة
8. SIGN OUT
```

**مهم:** الصفحات وأوامر `ICAction` الدقيقة لتسجيل المواد **لم تُلتقط بعد**، لأنها لا تعمل إلا في فترة التسجيل، وهي **الأسبوع القادم**.

### خطة الالتقاط (بلا أي مخاطرة)

1. تسجّل أنت الدخول في المتصفح المدمج، و**تسجّل موادك بنفسك** كما تفعل عادةً.
2. في الوقت نفسه أسجّل طلبات الشبكة والصفحات من التبويب: المسارات، و `ICAction`، والحقول المخفية، والردود، ورسائل الخطأ.
3. تُحفظ العينات بعد تجهيلها في `test/fixtures/peoplesoft/enroll/`.
4. من هذه العينات يُبنى التدفق، ويُختبر على بوابة مزيّفة تعيد تشغيل نفس الردود.

بهذه الطريقة لا يكتب رعد شيئاً في حساب أحد قبل أن يُختبر على تسجيل حقيقي التقطناه.

## أين يعمل البوت

### v1: في المتصفح (مجاني، بلا تخزين على السيرفر)

- المهمة تُحفظ في IndexedDB مع كل تغيير في حالتها.
- قفل `navigator.locks` يمنع تنفيذ المهمة مرتين إذا فُتح التطبيق في تبويبين.
- إذا أُغلق التطبيق أثناء المهمة، تُستأنف عند فتحه التالي من آخر حالة. والضمانة 3 تمنع التكرار.
- كل محاولة طلب HTTP مستقل إلى الحافة يفتح جلسة جديدة.

### v2: في الخلفية (اختياري، لاحقاً)

- Cloudflare Workflows لمهام تستمر وقتاً طويلاً، مع إشعار Web Push عند الانتهاء.
- **التكلفة على الخصوصية:** يجب حفظ بيانات الدخول مشفّرة على السيرفر طوال مدة المهمة. يفعّله الطالب صراحةً لكل مهمة، وتُحذف البيانات فور الانتهاء.

## ما يراه الطالب

- **زر رعد في وسط الشريط السفلي** يعرض حالته في كل الشاشات: ساكن، أو يعمل (وميض)، أو يعيد المحاولة، أو نجح، أو يحتاجك. التفاصيل في [06-design-system.md](06-design-system.md#رعد-في-الواجهة).
- **رأس شاشة رعد:** نقطة وكلمة واحدة، مثل `● جاهز` أو `● يعمل` أو `● محاولة 2/5` أو `○ بلا اتصال`.
- **صفحة المهمة:** خط زمني مختصر، كل سطر فيه كلمة وعلامة، بلا شروحات:

```
SIGN IN            ✓   0.8s
OPEN ENROLLMENT    ✕   timeout
SIGN IN            ✓   0.9s   new session
OPEN ENROLLMENT    ✓   1.2s
ADD PYBIO 101      ✓
VERIFY             ✓
```

## إحصاءات البوت (للإدارة، مجهولة المصدر وباختيار الطالب)

```ts
{ jobType, outcome, attempts, sessionResets, errorClasses: string[], durationMs, appVersion }
```

لا رقم جامعي، ولا اسم، ولا IP (Analytics Engine لا يحفظه)، ولا معاملات المهمة.
